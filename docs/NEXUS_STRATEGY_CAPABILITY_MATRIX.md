# Nexus Strategy Capability Matrix

This matrix defines what each Nexus strategy is uniquely allowed to say. Market reads describe the session. Strategy reads describe whether a specific Nexus lane can use that session.

## Strategy Read Contract

Nexus uses two related contracts:

- **Internal strategy signal contract:** full-fidelity payload generated by Redis and DB strategy workers for audit, execution gating, replay, and debugging.
- **Public strategy read contract:** sanitized API/UI payload that exposes only trader-readable summaries and safe trade-expression guidance.

The internal contract is allowed to contain raw evidence. The public contract must be derived from the internal contract through an allowlist sanitizer.

## Internal Strategy Signal Contract

Internal Redis and DB strategy payloads may contain:

| Field group | Allowed internally | Purpose |
|---|---|---|
| Identity | `signal_id`, `candidate_id`, `candidate_version`, `strategy`, `symbol`, `session_date`, `entry_time`, `window_start`, `window_end`, `source` | Stable lifecycle tracking. |
| Canonical reads | `direction_read`, `trade_action_read`, `signal_stage` | Shared strategy lifecycle language. |
| Raw contract reference | `raw_symbol`, `selected_contract_ref`, `expiry`, `strike`, `option_type`, `structure` | Exact contract continuity across `WINDOW_VIEW`, `INTERMEDIATE`, and `BET`. |
| Quote / execution evidence | bid, ask, mid, quote timestamp, quote age, valid-until timestamp, spread/tradability fields | Internal fillability and freshness gates. |
| Greeks / vol evidence | delta, gamma, IV, IV rank, ATM IV, pricing lag, cheap-side fields | Strategy calculations and audit. |
| Flow / premium evidence | call premium, put premium, total premium, aggressor/sweep evidence, lead-contract premium | Strategy gates, replay, and diagnostics. |
| Market-read snapshot | regime, volatility, flow, price location, trade quality, invalidation, timing, liquidity, event reliability, position management labels and raw supporting values | Explains why the strategy agreed or stood down. |
| Risk / lifecycle evidence | stop/guard policy, invalidation condition, blocked reason, missing inputs, gate results | Execution gating and post-session review. |
| Freshness / provenance | materialized time, emitted time, materialization lag, max lag, worker name/version, replay scope | Trust, latency, and replay correctness. |

Internal payloads can include sensitive or raw live option data because they are not the UI contract. They must still preserve provenance so downstream sanitizers know which values are derived and which are raw.

| Field | Meaning |
|---|---|

| `candidate_id` | Stable candidate identifier shared across lifecycle rows. |
| `candidate_version` | Incremented when selected contract/expression changes. |

| `strategy_vehicle` | Safe vehicle family, not a raw contract feed. |
| `strategy_direction` | `bullish`, `bearish`, or `neutral`. |
| `confidence` | Sanitized confidence score or confidence bucket. |

The UI may show the strategy read and safe trade expression. It must not expose raw live option prints, full bid/ask/mid, greeks, IV, raw contract symbol, or premium totals. Limit guidance is allowed only when derived from the internal selected-contract quote and returned as a rounded, trader-safe value.

## Read Windows And Trade Windows

Every Nexus strategy has two window sets:

- **Read windows:** all completed market-context windows. These run all day and explain what the strategy sees, even when no trade is allowed.
- **Trade windows:** researched strategy-entry windows from backtests/code. These are the only windows where `INTERMEDIATE` or `BET` lifecycle rows may be emitted.

Read windows and trade windows must not be collapsed into one concept. A strategy should educate the trader all day, but it should only create trade candidates during its approved trade windows.

Read-window rules:

- Emit one `WINDOW_VIEW`, `CHOP`, `BLOCKED`, or `SKIPPED` read per configured strategy/symbol/read window.
- Directional `WINDOW_VIEW` rows use `trade_action_read = watch` and `signal_stage = initial`.
- Directional `WINDOW_VIEW` rows may include a safe public trade expression when the strategy has selected an internal contract.
- `range_chop`, `BLOCKED`, and `SKIPPED` reads should explain why no directional expression is shown.

Trade-window rules:

- `INTERMEDIATE` may only be emitted inside the strategy's approved trade windows.
- `BET` may only be emitted after an eligible `INTERMEDIATE` or equivalent final trade gate inside an approved trade window.
- A trade lifecycle should preserve the same selected contract reference from directional `WINDOW_VIEW` to `INTERMEDIATE` to `BET`.
- If the selected contract changes, emit a new `candidate_version` rather than silently mutating the prior candidate.

## Strategy Conditions By Lifecycle Stage

Every strategy has three lifecycle stages:

- **Initial:** all-day `WINDOW_VIEW`, `CHOP`, `BLOCKED`, or `SKIPPED` read.
- **Intermediate:** candidate/watch state inside an approved trade window.
- **Final:** bet/exit/final-block state after final execution, model, spread, or risk gates.

Shared initial requirements:

- The read window exists and has enough materialized/live data to form a view.
- Required strategy fields are present or the row becomes `BLOCKED`.
- Direction is mapped to `direction_read = bull`, `bear`, or `range_chop`.
- Directional initial rows use `trade_action_read = watch` and `signal_stage = initial`.

Shared DB candidate requirements:

- `readiness_status = ready`
- `daily_context_status IN (ready, healthy)`
- `final_quote_status = fresh_quote_asof_window`
- `lead_contract_raw_symbol IS NOT NULL`
- `lead_quote_mid IS NOT NULL`
- If realtime lag is configured, `now()` and `materialized_at_utc` must be inside the allowed lag after window end.
- The strategy-specific candidate gates below pass.

Shared final requirements:

- The candidate remains inside an approved trade window.
- The selected contract/expression remains fresh and tradable.
- The same `candidate_id` / selected contract is preserved, or a new `candidate_version` is emitted.
- Strategy-specific final gates below pass.

### Raw Feed Quality Rules

- Raw OPRA trades alone are not enough for most strategy gates; they need quote context for aggressor, sweep, pricing lag, tradability, and final entry guidance.
- A strategy may form a `WINDOW_VIEW` from partial inputs, but missing quote/Greek/context inputs must produce `BLOCKED`, `CHOP`, or degraded quality instead of a false trade candidate.
- DB replay must use as-of-window quotes and contract state. Latest contract state after the window is not acceptable for deciding a historical window.
- Daily/EOD structural context can support a live read, but the payload must keep provenance visible because it is not tick-by-tick live.

## Canonical Lifecycle Reads

Every strategy signal or strategy window read must carry all three canonical reads:

| Payload decision | `direction_read` | `trade_action_read` | `signal_stage` | Meaning |
|---|---|---|---|---|
| `WINDOW_VIEW` with bullish sentiment | `bull` | `watch` | `initial` | Directional read only. Watch the setup; it is not a candidate or bet yet. |
| `WINDOW_VIEW` with bearish sentiment | `bear` | `watch` | `initial` | Directional read only. Watch the setup; it is not a candidate or bet yet. |
| `WINDOW_VIEW` with chop/neutral sentiment | `range_chop` | `stand_down` | `initial` | No directional trade expression should be shown. |
| `BLOCKED` / `SKIPPED` / `NO_BET` | `range_chop` unless a safe direction is known | `stand_down` | `initial` | Explain why the strategy cannot be used. |
| `WATCH` | `bull` or `bear` | `watch` | `initial` | Directional near-miss or review candidate. |
| `INTERMEDIATE` | `bull` or `bear` | `watch` | `intermediate` | Candidate passed strategy gates, but is not final trade permission. |
| `BET` | `bull` or `bear` | `bet` | `final` | Final trade signal. |
| `LIQUIDATE` / `FINAL_BLOCKED` | Existing position direction if known | `stand_down` | `final` | Exit or final block state. |

All `WINDOW_VIEW` rows must be `trade_action_read = watch` and `signal_stage = initial` when they are directional. A directional `WINDOW_VIEW` may include safe expression details such as option type, expiry, strike, quote freshness, derived limit guidance, and risk/invalidation notes. A `range_chop`, `BLOCKED`, or `SKIPPED` read should not show a trade expression.

| `etf_put_credit_open30_spread` | `defined_risk_bullish_credit` | Bullish open30 call dominance where defined-risk credit is the better expression. | High IV rank, no valid put spread candidate, stale leg quotes. | `put_credit_spread` |
| `etf_call_credit_open30_spread` | `defined_risk_bearish_credit` | Bearish open30 put dominance where defined-risk credit is the better expression. | High IV rank, no valid call spread candidate, stale leg quotes. | `call_credit_spread` |

## Redis And DB Alignment

- Redis path attaches `strategy_read` fields to window views, blocked views, intermediate candidates, final bets, spread bets, and final blocks.
- DB replay path attaches the same top-level safe fields and nested `strategy_read` object to `live.nexus_strategy_signal.payload_json`.
- DB `WATCH` rows use `strategy_action = watch`; DB `INTERMEDIATE` rows use `strategy_action = candidate`.
- Redis final `BET` rows use `strategy_action = bet`.
